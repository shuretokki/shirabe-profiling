Read the properties of `ProfileReport` to use the results in your own code, with no need to open the HTML file. This is the way to check a table in a test, a notebook, or a scheduled job.

## Prerequisites

- shirabe-profiling 0.2.0 or newer
- A table to profile. This guide uses the homes table.

## Steps

::steps

### Build the report once

Every property below reads from the same report, so build it a single time:

```python
from shirabe_profiling import ProfileReport
from shirabe_profiling.datasets import make_homes

df = make_homes()
report = ProfileReport(df, target="price")
```

### Read the size of the table

Use `overview` to see the rows, the columns, the missing cells, and the duplicate rows:

```python
for key in ("n_rows", "n_columns", "missing_cells", "duplicate_rows"):
    print(key, report.overview[key])
```

```text
n_rows 2000
n_columns 11
missing_cells 179
duplicate_rows 0
```

### Read the statistics of a column

Use `stats` to see the numbers of one column, and `column_types` to see how the report sorted it:

```python
print(report.column_types["price"].name)
for key in ("mean", "median", "skewness"):
    print(key, round(report.stats["price"][key], 3))
```

```text
NUMERIC
mean 596137.0
median 481000.0
skewness 2.283
```

The mean is far above the median, which is what a positive skew looks like.

### Read the alerts

Use `alerts` to see what the report flagged. Each alert holds the column, the type, the value, and the details:

```python
high = [a.column for a in report.alerts if a.alert_type.name == "HIGH_MISSING"]
print(high)
```

```text
['lot_m2']
```

### Read a correlation

Use `correlations` to get the matrix of each method. A matrix is a Polars table with one row per column:

```python
import polars as pl

pearson = report.correlations["pearson"].matrix
value = pearson.filter(pl.col("column") == "price").select("area_m2").item()
print(round(value, 3))
```

```text
0.583
```

### Save the results as JSON

Use `to_json` to write the results to a file, or `to_dict` to get them as a Python dict:

```python
report.to_json("report.json")
print(list(report.to_dict()))
```

```text
['title', 'overview', 'columns', 'alerts', 'correlations', 'interactions', 'target']
```

## Stop a pipeline when the data is not fit

Raise an error when the report finds a leaking column, so that a scheduled job does not train on it:

```python
leaks = [a.column for a in report.alerts if a.alert_type.name == "TARGET_LEAKAGE"]
if leaks:
    raise SystemExit(f"Target leakage in: {', '.join(leaks)}")
```

```text
Target leakage in: agent_commission
```

The job exits with a non-zero code, so a CI system marks the step as failed. Use the same pattern for other alert types, such as `HIGH_MISSING`.

## Troubleshooting

If `report.correlations["pearson"]` raises a `KeyError`, the report was built in `overview` mode. That mode skips the correlations, so the property is empty. Build the report in the default `complete` mode to get them. Follow [Change the settings](/essentials/change-the-settings) to see how.
