The report sorts every column into one of six types, and the type decides which statistics, charts, and alerts the column gets. It reads the Polars data type first, and it looks at the values only for text.

## The six types

| Type | Polars data types | Alerts it can raise |
| --- | --- | --- |
| `NUMERIC` | Integers and floats | `HIGH_MISSING`, `CONSTANT`, `HIGH_CARDINALITY`, `HIGH_ZEROS`, `SKEWED` |
| `CATEGORICAL` | Strings with many repeated values | `HIGH_MISSING`, `CONSTANT`, `HIGH_CARDINALITY`, `IMBALANCED`, `UNIFORM` |
| `BOOLEAN` | `Boolean` | `HIGH_MISSING`, `IMBALANCED` |
| `DATETIME` | `Date`, `Datetime`, `Time`, `Duration` | `HIGH_MISSING`, `CONSTANT` |
| `TEXT` | Strings with mostly distinct values | `HIGH_MISSING`, `CONSTANT` |
| `UNSUPPORTED` | Any other data type, such as lists | None |

The `HIGH_CORRELATION` and `TARGET_LEAKAGE` alerts cover pairs of columns, so they do not belong to one type. Read [Alerts](/concepts/alerts) for every rule.

## See the type of each column

Print `column_types` to see how the report sorted the columns of a small table:

```python
from datetime import date

import polars as pl

from shirabe_profiling import ProfileReport

df = pl.DataFrame(
    {
        "price": [1.5, 2.0, 3.5, 4.0],
        "has_pool": [True, False, True, True],
        "listed": [date(2026, 1, 1), date(2026, 1, 2), date(2026, 1, 3), date(2026, 1, 4)],
        "district": ["north", "south", "north", "south"],
        "note": ["a sunny home", "near the park", "needs a roof", "quiet street"],
        "tags": [[1], [2], [3], [4]],
    },
)
report = ProfileReport(df)
for name, kind in report.column_types.items():
    print(name, kind.name)
```

```text
price NUMERIC
has_pool BOOLEAN
listed DATETIME
district CATEGORICAL
note TEXT
tags UNSUPPORTED
```

## How the report picks a type

The report checks each column in this order and stops at the first match:

1. A `Boolean` column is `BOOLEAN`.
2. A `Date`, `Datetime`, `Time`, or `Duration` column is `DATETIME`.
3. An integer or float column is `NUMERIC`.
4. A string column is `TEXT` or `CATEGORICAL`, depending on its values.
5. Any other column is `UNSUPPORTED`.

An integer column stays `NUMERIC`, even when it holds only a few codes such as 1, 2, and 3. Cast it to a string first if you want the report to treat it as a category.

## Tell text from categories

The report divides the number of distinct values by the number of values that are not missing. If the result is above `text_unique_ratio`, the column is `TEXT`. If not, it is `CATEGORICAL`. The default is 0.5.

In the table above, `district` has two distinct values in four rows, so its ratio is 0.5. That is not above 0.5, so the column is `CATEGORICAL`.

Lower the limit to see the column become text:

```python
report = ProfileReport(df, text_unique_ratio=0.2)
print(report.column_types["district"].name)
```

```text
TEXT
```

Set the limit high, such as 0.95, if your categories have many distinct values, such as a city column with thousands of cities.

## Handle an unsupported column

The report lists an `UNSUPPORTED` column but computes nothing for it, so it has no statistics and no alerts. To profile it, turn it into a supported type first. For example, join the items of a list of strings into one string with `pl.col("tags").list.join(",")`.
